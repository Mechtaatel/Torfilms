# Публичный каталог и отдельное управление

## Что подготовлено

Torfilms по умолчанию работает как сайт просмотра (`viewerOnly: true`). Он не
загружает интерфейс аккаунтов, не показывает редакторы и не отправляет токены
Torfilms. Публичный backend по умолчанию запрещает `/auth`, `/requests`, `/admin`
и запись `/catalog/*`, независимо от Origin и наличия токена.

Для будущего отдельного сайта управления нужен отдельный процесс backend с
`TORFILMS_ADMIN_ENABLED=1`, отдельный origin, HTTPS и проверка серверных ролей.
Не включайте этот флаг в публичном процессе просмотра. Сам по себе другой домен
или CORS не заменяет авторизацию. Отдельный административный сайт ещё не развёрнут.

## Порядок подключения Neon

1. В нужной ветке Neon включите Data API. **Не включайте Grant public schema access**.
   Для гостевого доступа можно использовать Managed Better Auth: посетителю не
   требуется регистрация, но Data API использует короткоживущий anonymous JWT.
2. Выполните `migrations/001-public-catalog.sql` в SQL Editor от владельца таблиц
   Torfilms. Роли `anonymous` и `authenticated` уже должны существовать.
   Миграция намеренно отзывает их доступ к исходному каталогу и аккаунтам.
   Если база используется другими приложениями, сначала проверьте влияние прав.
3. В Data API выставьте exposed schemas только `catalog`, не `public`. Обновите
   schema cache. Разрешите CORS для origin сайта (GitHub Pages — без пути `/Torfilms`).
   Не публикуйте привилегированные RPC и не выдавайте гостям дополнительные роли.
4. Проверьте у всех владельцев таблиц default privileges: будущие таблицы не должны
   автоматически выдаваться API-ролям. SQL меняет defaults только выполняющего его
   владельца. Проверьте унаследованные права через членство ролей отдельно.
5. В runtime-config.js укажите `neonDataApiUrl` — HTTPS Data API URL из консоли,
   обычно заканчивается `/rest/v1`, и `neonAnonymousTokenUrl` — URL Managed Better
   Auth, заканчивающийся `/auth/token/anonymous`. Это публичные URL, **не** DATABASE_URL,
   не Neon API key и не постоянный JWT. Клиент получает гостевой токен и обновляет
   его после 401. Токен хранится только в памяти текущей страницы.
6. Для Pages задайте repository variables `TORFILMS_NEON_DATA_API_URL` и
   `TORFILMS_NEON_ANONYMOUS_TOKEN_URL`. Сборка переносит их в runtime-config.js.
   Публикацию выполняет владелец проекта; агент ничего не отправляет на GitHub.

Если URL пока пустой, чтение остаётся на существующем backend. Если URL указан,
ошибки Neon видны пользователю, без скрытого переключения обратно на backend.

## Контракт

Логический вызов `/catalog/movies` на клиенте становится прямым запросом
`GET <Data API URL>/movies?select=movie&order=id.asc&limit=200&offset=0`
с `Accept-Profile: catalog`. Это синтаксис PostgREST: схема выбирается заголовком,
а не добавлением `/catalog` к REST URL. Следующие страницы запрашиваются по offset.

Представление содержит `id` и `movie` с явным списком полей, включая вложенные
сезоны и источники. Нет полного payload, revision, torrentBase64, magnet,
аудиометаданных и пользовательских данных. Изменение исходной карточки сразу
видно через view, отдельная синхронизация не нужна. Исходная раздача и метаданные
получаются плеером через backend `/catalog/source/...` при запуске.

View намеренно использует права владельца и security_barrier: API-ролям не нужен
доступ к исходной таблице. Владелец должен оставаться доверенным серверным
владельцем; не назначайте владельцем anonymous/authenticated. RLS без публичных
политик включается на исходных таблицах; сервер-владелец сохраняет доступ.

## Обязательная проверка перед переключением

В отдельной тестовой ветке: гостевой GET view работает; SELECT исходного payload
и accounts запрещён; INSERT/UPDATE/DELETE view и таблиц запрещены как для anonymous,
так и authenticated. Тестируйте запись на тестовой ветке, не на живых карточках.
В SQL Editor можно использовать BEGIN; SET LOCAL ROLE anonymous; SELECT ...;
ROLLBACK для проверки прав. Повторите для authenticated. Проверьте отсутствие
доступных функций с SECURITY DEFINER, позволяющих обойти ограничения.

После этого проверьте Network в браузере: каталог идёт непосредственно в Neon,
серии и качества доступны, запуск плеера по-прежнему обращается к мосту.
Локальные unit-тесты не заменяют эти проверки реальных прав в Neon.

Документация: https://neon.com/docs/data-api/access-control
и https://neon.com/docs/data-api/get-started
